# PC / 移动端聊天界面适配任务书

任务编号：UI-RESP-20261008。制定方：backend；执行方：现有 frontend agent。状态：已下发，等待 frontend ACK。用户要求是 PC 与手机均可完整使用的类微信聊天界面，不是将桌面三栏缩小后塞进手机。

## 一、目标与边界

保留已实现的登录/注册、会话列表、联系人/好友申请、私聊、群聊、会话详情、未读/已读、在线/输入状态、主题切换和注销。PC 保持多栏效率；手机采用单屏层级导航，能从列表进入聊天、查看详情并返回。

- frontend agent 只修改自己负责的 `frontend/`、`docs/`，无需改 `contracts/`。本方不跨写其源码。
- `session.txt` 只追加，每条不超过600字；frontend 先 ACK，再按任务编号汇报证据与阻塞。
- REST/WS 契约、后端认证、QJQ 自动好友规则、HTTP 部署入口及原主站不变。
- 不引入新框架或新平台工程；不新增尚无后端支持的朋友圈、发现、支付、音视频、附件、个人设置接口或空壳按钮。复用 Vue / Pinia / Router / 现有主题与图标。
- 不 commit/tag，不擅自部署、不清理生产数据；不要再向生产注册探针账号。测试凭据只能在内存中，不能写入文件、截图、报告或通道。
- 重要设计决策及验收记录由 frontend 写入 `docs/09-responsive-ui.md`；本任务书留在 backend 是为遵守现有文件所有权，而非要求前端修改 backend。

## 二、当前问题依据

1. `styles/theme.css` 定义 rail=60px、sidebar=280px，ConversationList / ContactPanel 固定宽度，ChatView 横向 flex。375px 手机剩余内容宽度仅35px；不能只用 overflow hidden 遮住问题。
2. AppRail 是 PC 竖侧栏，MessagePane 没有移动端回列表入口。移动端需要列表与正文互斥展示，以及符合历史栈语义的返回。
3. Login / Register 卡片为固定340px；AppModal 默认420px、建群440px，窄屏有溢出风险。
4. 根布局使用100%高度，发送按钮30px、详情按钮28/30px，没有移动软键盘、安全区与触控专项策略。
5. WS handlers 按 activeId 判定正在看会话，MessagePane 会随消息更新 markRead。隐藏页面但仍保留组件时，会有列表收到消息却被自动已读的风险。
6. 先前修好的深链/F5历史加载依赖 awaitingSummary / enterGen，不得在布局重构时改回裸 return 或引入重复请求。

## 三、产品布局与导航

断点按 CSS 视口宽度判定，不用 User-Agent；CSS 与 JS 若均需判断，必须使用同一断点定义。

| 宽度 | 布局 | 行为 |
|---|---|---|
| <768px | 手机单栏全屏 | 默认会话列表或联系人列表；底部仅「聊天」「联系人」两项；主题/注销放入可达的更多入口 |
| 768–1023px | 平板紧凑多栏 | 侧栏可缩为48px，列表建议240px，消息/详情使用剩余宽度；不出现横向滚动 |
| >=1024px | PC 多栏 | 保留竖侧栏、列表、消息/详情三块，侧栏60px、列表280px可沿用；窗口放大缩小都可操作 |

手机导航状态：

```text
聊天列表 / 联系人列表（底部导航可见）
  -> 私聊 / 群聊（全屏正文，顶部返回，底部导航隐藏）
       -> 会话详情（顶部返回该聊天，独立滚动）
  -> 好友申请 / 搜索加好友（清晰返回联系人）
  -> 发起群聊（适合手机的弹层或页面，不改变业务）
```

- 顶部返回不是单纯调用 router.back()：用户直接打开深链时必须有站内列表回退，不能把人退到原主站或外部页面。
- 保留现有 route names、参数与路径结构；根据 route 决定当前屏。route / activeId / 可见性必须一致，浏览器前进后退、直接深链和刷新同样成立。
- 从列表进入消息，再返回列表，恢复来源 tab、搜索词与列表滚动位置；详情返回原会话。不得把隐藏的详情或历史页面视为正在读消息。
- 手机横竖屏、PC拖动窗口跨断点时，保留账号、当前路由、当前会话、草稿与消息，不重新登录、不重复建立WS或重复提交消息。
- 列表未读标记及底部聊天tab未读提示正常；所有主题/注销入口在手机上可达。只提供已实现的功能，不伪造微信其它tab。

### R2 — 布局骨架与手机导航

重点文件：`App.vue`、`styles/main.css`、`styles/theme.css`、`views/ChatView.vue`、`components/layout/AppRail.vue`、`ConversationList.vue`、`ContactPanel.vue`、`stores/ui.ts`、必要的路由适配和移动导航组件。

### R3 — 聊天、输入框与移动视口

重点文件：`views/MessagePane.vue`、`components/message/MessageComposer.vue`、`MessageBubble.vue`、必要的布局工具。

要求：

- 消息区独立滚动，标题与输入区稳定；采用100dvh及兼容回退，有必要时谨慎配合VisualViewport处理键盘高度。避免重复扣减高度或安全区；监听需清理。
- 启用需要的viewport-fit/safe-area-inset处理；刘海/底部手势区不遮住导航、发送键或消息。不能禁止浏览器缩放。
- 输入框聚焦、软键盘打开/收起、地址栏伸缩、横竖屏切换后，输入与发送仍可见；无页面上下双重滚动、严重跳动或键盘挡住操作。
- 手机上的主输入使用至少16px字号避免iOS自动放大；发送、返回、更多、关闭等触控热区至少44x44 CSS px，可用padding扩大，不要求图标本身44px。
- PC保留Enter发送、Shift+Enter换行；手机多行输入优先Enter换行，显式发送键发送。保留中文IME composition保护，不在选词确认时意外发送。
- 长中文、多行、连续英文/URL文本都可换行；左右气泡、头像、时间、发送失败重试不出屏，系统消息可读。
- 保留awaitingSummary/enterGen深链修复、历史翻页视口保持、读历史时新消息不强行吸底、幂等乐观去重。

验收：不能仅提交手机截图；须实际测试输入、发送、返回与滚动。自动化模拟小视口不能宣称真机软键盘通过。

### R4 — 非聊天页面和弹层

要求：认证卡片宽度受视口约束，短屏/键盘时可滚动、按钮不消失；联系人搜索、申请通过/拒绝、建群选人/群名、详情成员/改名/邀请等已有流程均可操作。弹层最大宽高受视口和安全区约束，内容区滚动、关闭与确认可达；桌面焦点陷阱/ESC与移动触控并存。浅/深主题全流程可读，不能只修主页。

验收：320px手机能完成注册登录、加好友/接受、进入聊天、建群/查看详情与注销；弹层不伸出屏幕，关闭后焦点合理恢复。

### R5 — 路由、已读和连接回归

重点文件：布局状态、`stores/conversation.ts`、`ws/handlers.ts`、`MessagePane.vue`相关测试；不修改协议。

要求：路由切到列表/联系人时正确清除或调整activeId；仅「当前消息正文确实可见且浏览器页面可见」才自动markRead。CSS隐藏但仍mounted的组件不能继续吞掉未读、上报typing或强行滚动。会话详情/联系人不等于正在阅读消息。返回、弹层关闭、缩放不重复connect，WS reconnect与一次性ticket行为保持。

验收：A手机停在列表时，B发消息，A看到未读且没有自动提交该消息已读；A进入该会话后才消除未读。同样检查联系人、后台标签页与详情。冷启动深链、F5、前进后退、缩放跨断点后无历史丢失、重复气泡或重复发送。

# 正式发布标准与责任任务

日期：2026-10-08。范围：既有文字聊天 MVP；不扩展支付、朋友圈、音视频。第三方品牌、图标或商标不得进入产品界面。证据必须对应同一候选版本源码指纹与产物。

## 发布门禁

- P0：安全、隐私、数据损失风险；未关闭直接阻止发布。
- P1：核心功能、跨端完整性、恢复能力；正式发布前关闭，不以接口单测豁免。
- P2：非核心体验；可按责任人、交付时间与明确风险排期。
- 状态：待 ACK、实施中、待验收、通过、阻塞。没有实现证据不能推进。
- 自动门禁全绿仅代表技术检查通过；HTTPS、浏览器/真机、运维、合规单独验收。

任务表记录下发时的初始状态；实际已验结果和仍失败反例见 `current-status.md`。工程师未正式ACK，不虚构承诺与交付时间。

## 执行顺序与交付格式

1. frontend先确认SEC-02，与在途移动端一起设计隐私隔离/已读；backend并行出SEC-01实施与权限清单。
2. frontend R1/R2按原任务回同步，随后R3–R6、失败恢复、失效路由、依赖。backend恢复/限流/容量/安全配置。
3. 每次SYNC给任务ID、文件、命令/退出码、证据、未验项，每条≤600字。时间由工程师ACK给出，PM不虚构。
4. PM复跑隔离门禁和反例；真机/证书/运营权限拿不到明确保留阻塞。
5. 首发单机小规模文字聊天，容量结论只适用于实测配置。扩容/多节点另行设计。

## 生产审批

维护窗口前确认域名、候选版本、备份、回滚负责人、停止条件与权限。不用正式用户开展自动发消息/建群/注册验收；使用本地或隔离预发布。TLS/探针删除单独审批，禁止绕过安全限制。任何门禁不全，保持NO-GO。
